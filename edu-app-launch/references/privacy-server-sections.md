# B형(서버 저장) 앱 방침에 추가할 절

Firebase, Supabase, 앱스스크립트(구글 시트) 등에 학생 정보를 저장하는 앱은 A형 템플릿의
"수집하지 않아요", "기기 안에서만" 문장을 모두 지우고 아래 절을 넣는다. 표 내용은 코드에서
확인한 사실로만 채운다. 모르는 값(보관 기간 등)은 추측하지 말고 사용자에게 묻는다.

## 1. 수집하는 개인정보와 목적

| 항목 | 목적 | 필수/선택 |
|---|---|---|
| 예: 학생 이름(또는 별명) | 활동 결과 표시·교사 확인 | 필수 |
| 예: 학급 코드 | 같은 반 결과 모아 보기 | 필수 |

- 가능한 한 실명 대신 별명·번호를 쓰도록 안내하는 문장을 넣는다.

## 2. 보유 기간과 파기

- 보유 기간: 예) 학년도 종료 후 30일, 또는 교사가 삭제할 때까지
- 파기 방법: 데이터베이스에서 영구 삭제, 복구할 수 없게 처리
- 자동 삭제 기능이 없으면 "운영자가 매 학년도 말에 삭제해요"처럼 실제 운영 방식대로 적는다.

## 3. 처리 위탁과 국외 이전

| 받는 곳 | 위탁 업무 | 이전 국가·방법 | 항목 | 보유 기간 |
|---|---|---|---|---|
| Google LLC (Firebase) | 데이터 저장 | 미국 등, 네트워크 전송 | 1항 항목 | 2항과 같음 |
| Supabase Inc. | 데이터 저장 | 선택한 리전(예: 서울이면 국내) | 1항 항목 | 2항과 같음 |
| Vercel Inc. | 호스팅 | 미국, 네트워크 전송 | 접속 기록 | Vercel 정책에 따름 |

- 리전은 프로젝트 설정에서 확인한다(Firebase 콘솔, Supabase 프로젝트 설정).

## 4. 만 14세 미만 아동

- 만 14세 미만 학생의 정보를 서버에 저장하면 법정대리인 동의가 필요할 수 있다. 학교 수업 활용이라면
  "학교의 수업 운영 범위에서 교사가 관리해요"처럼 실제 운영 방식을 적고, 학교 방침(가정통신문 동의 등)과
  맞는지 사용자에게 확인을 권한다.

## 5. 정보주체의 권리

- 열람·정정·삭제 요청 방법(운영자 이메일, 교사에게 요청 등)과 처리 기한(예: 10일 이내)을 적는다.

## 6. 안전성 확보 조치

- 데이터베이스 접근 규칙(Firestore Rules, Supabase RLS)을 적용했는지 코드에서 확인하고, 적용했으면 적는다.
  적용하지 않았으면 방침에 쓰기 전에 사용자에게 먼저 알린다. 이것은 방침 문구보다 급한 보안 문제다.
