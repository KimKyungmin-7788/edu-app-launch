# 교육용 앱 배포 점검

원칙: 템플릿을 그대로 붙이지 말고, 앱이 실제로 하는 일을 확인한 뒤 그에 맞게 적는다. 사실과 다른 방침은 없는 것보다 나쁘다.

## 0. 운영자 정보

운영자 이름과 연락 이메일을 사용자에게 묻는다. 방침·약관의 `{{OPERATOR}}`, `{{EMAIL}}`에 들어가 공개된다는 점을 알린다. 답을 받기 전에는 채우지 않는다.

## 1. 앱 파악

코드를 읽고 아래를 표로 정리해 보여 준다. 이후 단계는 모두 이 표를 근거로 한다.

- 외부에서 불러오는 도메인 (`<script src`, `<link href`, `@import`, `fetch(` 대상)
- 서버로 보내는 데이터 (`fetch`, Firebase/Supabase, `google.script.run`)
- 기기에 남기는 데이터 (`localStorage`, `indexedDB`, cookie)
- 학생 정보 입력·권한 (이름·사진·음성, 카메라·마이크·공유)
- 새기 쉬운 경로 (음성 합성, 외부 AI·번역 API, 분석 도구·광고)
- 폰트 (파일, `@font-face`, 외부 폰트 주소)
- 배포 방식 (Vercel, Netlify, 앱스스크립트)

서버 저장이 없으면 A형, 있으면 B형으로 분류한다.

## 2. 학생 정보 유출 점검

- 음성 합성은 기기 내장 음성(`voice.localService`)을 우선 고른다.
- 외부 API에 학생 이름·사진을 보내면 보내지 않게 바꾸자고 제안하고, 못 바꾸면 방침에 제공처로 적는다.
- 분석 도구·광고는 빼자고 제안한다.

## 3. 폰트 라이선스

`python3 scripts/check_fonts.py <앱폴더>`를 실행하고 결과를 보여 준다. 판단 기준은 `references/font-license.md`.

- 조치 필요: OFL 폰트 옆에 OFL.txt를 넣는다. 학교안심 글꼴은 [학교안심 글꼴 키트](https://github.com/KimKyungmin-7788/hakgyoansim-font-kit)의 `fonts/OFL.txt`를, 그 밖의 폰트는 원본에 들어 있던 파일을 쓴다(내용을 지어내지 않는다). 공공누리 폰트는 출처표시를 넣거나 교체한다.
- 학교안심 폰트를 woff2 등으로 변환하지 않고 원본 OTF를 쓴다.
- 확인 필요: 출처를 사용자에게 묻고, 모르면 학교안심 글꼴 키트의 폰트로 교체를 제안한다.
- 화면·이미지에는 출처표시가 필요 없다.

## 4. 보안 헤더

`templates/vercel.json`을 복사해 1단계에서 찾은 도메인만 허용하도록 CSP를 고친다(`references/csp-recipes.md`).
기존 `vercel.json`이 있으면 `headers`만 합친다. Permissions-Policy는 쓰는 권한만 `(self)`.
Netlify는 `_headers`로 옮기고, 앱스스크립트는 헤더를 못 바꾼다고 알린다.

## 5. 개인정보처리방침·이용약관

- `templates/privacy.html`, `terms.html`, `policy.css`를 앱 루트에 복사하고 `{{...}}`를 모두 채운다(`grep '{{'`로 확인).
- `<!-- EDIT -->` 부분을 1단계 표에 맞게 고치고, 없는 기능의 문장은 지운다.
- B형이면 `references/privacy-server-sections.md`의 절을 넣고 "저장하지 않아요" 문장을 고친다.
- 첫 화면 하단에 `/privacy`, `/terms` 링크를 단다.

## 6. 링크 미리보기

`templates/meta-snippet.html`을 `<head>`에 넣고, 대표 화면으로 `og.png`(1200×630)를 만들어 직접 열어 확인한다.

## 7. 확인

- 배포 전: `scripts/header_server.py <앱폴더>`로 헤더를 켠 채 주요 기능을 눌러 본다. CSP 위반·콘솔 오류 0개, 글꼴 정상 표시, 휴대폰 너비에서 방침 페이지 확인.
- 배포 후: `scripts/check_live.sh <주소> [/fonts/OFL.txt]`로 헤더·방침·미리보기·폰트 라이선스 파일을 확인한다.

## 마지막 보고

적용한 것, 확인 못 한 것, 사용자가 직접 확인할 폰트를 구분해 말한다. 방침·약관은 법률 검토 문서가 아니므로 학교 양식과 대조를 권한다.

## 이후 관리

앱 프로젝트의 `CLAUDE.md`(클로드 코드) 또는 `AGENTS.md`(코덱스)에 아래 규칙을 넣자고 제안하고, 확인받은 뒤 넣는다.

```
- 외부 스크립트·글꼴·API를 추가하면 CSP와 개인정보처리방침을 같이 고친다.
- 폰트는 OFL 폰트(학교안심 글꼴 등)만 쓰고, 폰트 파일을 넣을 때 원본 OFL.txt를 같은 폴더에 둔다.
- 라이선스를 확인할 수 없는 폰트는 넣지 말고 먼저 알린다.
```
