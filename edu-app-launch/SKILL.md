# 교육용 앱 배포 점검

이 문서의 `templates/`, `scripts/`, `references/` 경로는 이 SKILL.md가 있는 폴더 기준이다. 윈도우에서 `python3`가 없으면 `python`으로 실행하고, `.sh` 스크립트는 Git Bash로 돌리거나 같은 확인을 PowerShell로 한다.

## 원칙

- 템플릿을 그대로 붙이지 말고, 앱이 실제로 하는 일을 확인한 뒤 그에 맞게 고치고 적는다. 사실과 다른 방침은 없는 것보다 나쁘다.
- 사용자는 미성년 학생이고, 특수교육 앱은 장애·건강·상담 기록까지 다룰 수 있다. 판단이 애매하면 보내지 않고 저장하지 않는 쪽을 고른다.
- 코드로 고칠 일과 사람이 할 일(신고, 학교·교육청 확인, 키 재발급, 최신 법 조문 확인)을 나눈다. 사람이 할 일을 코드로 해결했다고 말하지 않는다.
- DB 접근 규칙, 로그인·가입 흐름처럼 쓰는 방식이 바뀌는 수정은 영향 범위를 알리고 승인받은 뒤 한다. 점검 범위 밖의 코드는 고치지 않는다.

## 1. 앱 파악

한 번에 앱 하나만 점검한다. 코드를 읽고 아래를 표로 정리해 보여 준다. 이후 단계는 모두 이 표를 근거로 한다.

- 외부에서 불러오는 도메인 (`<script src`, `<link href`, `@import`, `fetch(` 대상)
- 서버로 보내는 데이터: 어떤 학생 정보가 어디로 가는지 (`fetch`, Supabase/Firebase, `google.script.run`, AI API)
- 기기에 남기는 데이터 (`localStorage`, `indexedDB`, cookie)
- 학생 정보 입력·권한 (이름·사진·음성, 카메라·마이크·위치·공유)
- 계정·서버 기능 (로그인·가입, 교사·관리자 화면, DB 저장, 점수·결제, 알림 발송)
- 새기 쉬운 경로 (음성 합성, 외부 AI·번역 API, 분석 도구·광고)
- 폰트 (파일, `@font-face`, 외부 폰트 주소)
- 배포 방식 (Vercel, Netlify, 앱스스크립트)

서버 저장과 로그인이 모두 없으면 A형, 하나라도 있으면 B형으로 분류한다.

표를 보여 줄 때 방침·약관에 공개될 운영자 이름과 연락 이메일을 함께 묻는다. 답을 받기 전에는 `{{OPERATOR}}`, `{{EMAIL}}`을 채우지 않는다.

## 2. 학생 정보 유출 점검

- 음성 합성은 기기 내장 음성(`voice.localService`)을 우선 고른다.
- 외부 API에 학생 이름·사진·상담 내용을 보내면 보내지 않게 바꾸자고 제안하고, 못 바꾸면 방침에 제공처와 국외 이전으로 적는다.
- 비밀 키(AI·번역·문자 API 키, Supabase service_role 키, 서비스 계정 키)가 HTML, 클라이언트 코드, `VITE_`·`NEXT_PUBLIC_` 변수에 있으면 배포를 멈추고 알린다. 공개 페이지의 키는 누구나 복사해 쓴다. 공개해도 되는 키와의 구분은 `references/server-audit.md`의 "비밀 키".
- 분석 도구·광고는 빼자고 제안한다.

## 3. 서버·법적 점검

B형이거나, A형이라도 AI API·위치·알림·결제·권한 요청이 있으면 한다.

- B형이면 `references/server-audit.md`의 항목을 코드와 설정에서 확인한다. 학생 정보가 든 DB나 저장소를 아무나 읽고 쓸 수 있으면 다른 단계보다 먼저 알린다.
- `references/legal-checklist.md`에서 앱에 있는 기능의 행만 확인한다.
- 찾은 문제마다 원인(파일:줄), 최소 수정안, 회귀 위험, 확인 방법을 붙여 보여 주고, 승인받은 뒤 고친다.

## 4. 폰트 라이선스

`python3 scripts/check_fonts.py <앱폴더>`를 실행하고 결과를 보여 준다. 판단 기준은 `references/font-license.md`.

- 조치 필요: OFL 폰트 옆에 OFL.txt를 넣는다. 학교안심 글꼴은 [학교안심 글꼴 키트](https://github.com/KimKyungmin-7788/hakgyoansim-font-kit)의 `fonts/OFL.txt`를, 그 밖의 폰트는 원본에 들어 있던 파일을 쓴다(내용을 지어내지 않는다). 공공누리 폰트는 출처표시를 넣거나 교체한다.
- 학교안심 폰트를 woff2 등으로 변환하지 않고 원본 OTF를 쓴다.
- 확인 필요: 출처를 사용자에게 묻고, 모르면 학교안심 글꼴 키트의 폰트로 교체를 제안한다.
- 화면·이미지에는 출처표시가 필요 없다.

## 5. 보안 헤더

`templates/vercel.json`을 복사해 1단계에서 찾은 도메인만 허용하도록 CSP를 고친다(`references/csp-recipes.md`).
기존 `vercel.json`이 있으면 `headers`만 합친다. Permissions-Policy는 쓰는 권한만 `(self)`.
Netlify는 `_headers`로 옮기고, 앱스스크립트는 헤더를 못 바꾼다고 알린다.

## 6. 개인정보처리방침·이용약관

- `templates/privacy.html`, `terms.html`, `policy.css`를 앱 루트에 복사하고 `{{...}}`를 모두 채운다(`grep '{{'`로 확인).
- `<!-- EDIT -->` 부분을 1단계 표에 맞게 고치고, 없는 기능의 문장은 지운다.
- B형이면 `references/privacy-server-sections.md`의 절을 넣고 "저장하지 않아요" 문장을 고친다. 안전 조치는 3단계에서 확인된 것만 적는다.
- 첫 화면 하단에 `/privacy`, `/terms` 링크를 단다.

## 7. 링크 미리보기

미리보기 메타가 없거나 사용자가 원할 때 한다. `templates/meta-snippet.html`을 `<head>`에 넣고, 대표 화면으로 `og.png`(1200×630)를 만들어 직접 열어 확인한다.

## 8. 확인

- 배포 전: `scripts/header_server.py <앱폴더>`로 헤더를 켠 채 주요 기능을 눌러 본다. CSP 위반·콘솔 오류 0개, 글꼴 정상 표시, 휴대폰 너비에서 방침 페이지 확인. 빌드하는 앱은 `npm run build`가 통과하는지 보고, `vercel.json`을 결과 폴더(`dist` 등)에 복사한 뒤 그 폴더로 띄운다.
- B형이면 로그아웃 상태로 교사·관리자 주소에 직접 들어가 보고, 한 학생 계정으로 다른 학생의 데이터가 보이지 않는지 확인한다.
- 배포 후: `scripts/check_live.sh <주소> [/fonts/OFL.txt]`로 헤더·방침·미리보기·폰트 라이선스 파일을 확인한다.

## 마지막 보고

적용한 것, 확인 못 한 것, 사람이 할 일(신고·학교 확인·키 재발급·폰트 출처)을 나눠 말한다.
열린 DB, 노출된 비밀 키, 로그인 없이 열리는 교사·관리자 화면이 남아 있으면 "배포해도 된다"고 말하지 않는다.
방침·약관과 법적 점검표는 법률 검토 문서가 아니므로 학교 양식과 대조하고, 확정이 필요한 판단은 국가법령정보센터(law.go.kr)에서 최신 조문을 확인하라고 권한다.

## 바로 쓰기였다면: 저장 제안

이 SKILL.md를 스킬 폴더(`~/.claude/skills`, `~/.agents/skills` 등)가 아닌 임시 폴더에서 읽었다면, 마지막 보고 뒤 "이후 관리" 제안과 같은 메시지에서 한 번 묻는다. 선택지 도구가 있으면 쓰고, 없으면 번호로 묻는다(함께 고를 수 있다).

"다음부터 '배포 전 점검해 줘'만 말해도 되도록 이 점검을 스킬로 저장할까요?"
1. 이 컴퓨터에 저장 (모든 프로젝트에서 사용)
2. claude.ai 계정용 파일 만들기
3. 저장하지 않음

- 1번: 내려받은 `edu-app-launch` 폴더만 사용자 스킬 폴더에 복사한다. 클로드 코드는 `~/.claude/skills/`, 코덱스는 `~/.agents/skills/`. 같은 이름이 이미 있으면 덮어쓸지 먼저 묻는다. 바로 인식되지 않으면 새 세션을 열라고 안내한다.
- 2번: `edu-app-launch` 폴더를 zip으로 묶어 다운로드 폴더에 두고, Claude 설정의 스킬 메뉴에서 올리라고 안내한다. 계정에 올리는 일은 사람이 한다.
- 끝나면 임시 폴더를 지우고, 업데이트는 "edu-app-launch 최신으로 업데이트해 줘"라고 하면 된다고 알려 준다.

## 이후 관리

앱 프로젝트의 `CLAUDE.md`(클로드 코드) 또는 `AGENTS.md`(코덱스)에 아래 규칙을 넣자고 제안하고, 확인받은 뒤 넣는다.

```
- 외부 스크립트·글꼴·API를 추가하면 CSP와 개인정보처리방침을 같이 고친다.
- 로그인·DB 저장·AI API·결제를 새로 넣으면 배포 전에 edu-app-launch 3단계를 다시 한다.
- 비밀 키는 클라이언트 코드와 VITE_·NEXT_PUBLIC_ 변수에 넣지 않는다.
- 폰트는 OFL 폰트(학교안심 글꼴 등)만 쓰고, 폰트 파일을 넣을 때 원본 OFL.txt를 같은 폴더에 둔다.
- 라이선스를 확인할 수 없는 폰트는 넣지 말고 먼저 알린다.
```
